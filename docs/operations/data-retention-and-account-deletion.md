# 数据保留与账号注销矩阵

更新日期：2026-08-25

## 处理原则

账号注销分为“用户提交”和“平台完成”两阶段。提交后立即撤销所有会话；平台管理员完成保留评估后，由单一数据库事务执行去标识化、计数回收和异步对象清理入队。异步清理具备幂等键、指数重试和死信处置。

| 数据类型 | 注销完成时处理 | 保留原因/访问边界 |
| --- | --- | --- |
| 手机号 | 密文替换为删除标记，哈希换为随机不可逆值 | 防止与原号码重新关联 |
| 公开资料 | 昵称匿名化，头像、简介、职业标签清空 | 仅保留不可识别的占位记录 |
| 动态与评论 | 软删除，原文替换为统一删除说明，话题清空 | 保留外键结构用于审计和计数一致性，前台不公开 |
| 关注、收藏、点赞、分享、投票 | 删除关系并事务性回收计数 | 不保留个人互动轨迹 |
| 城市/机构成员、活动报名 | 删除关系并回收成员/报名计数 | 不再具有任何成员权限 |
| 用户发起的活动 | 取消未结束活动，通知任务入队 | 保留最小活动记录便于向参与者说明 |
| 工单 | 去除用户、姓名、联系方式和原始正文 | 保留非个人化的运营处理记录 |
| 媒体 | 状态改为拒绝，公开键清空，原图/公开对象异步删除 | 失败进入死信并由运营重放 |
| 举报、申诉、审核、审计 | 保留必要记录，不继续展示原公开内容 | 安全、争议处理和法定义务；仅授权运营可访问 |

## 验收断言

- 注销完成后用户不可登录，所有会话已撤销。
- 用户的动态、评论、头像和工单不再包含原个人内容。
- 城市、机构、活动和互动计数不得为负，且与关系表一致。
- 媒体清理任务必须有幂等键；重试用尽后必须进入死信并告警。
